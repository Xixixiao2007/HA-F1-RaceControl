# HA-F1-RaceControl

把 Home Assistant 里的 **F1 赛事控制消息**做成 Android 手机上的实时仪表。

比赛日你会盯着它看：红旗、安全车、双黄旗立刻强提醒；赛道当前状态一眼可见；
噪音默认过滤掉。

给 **Android 6.0 老设备**做的：不经过 WebView、不依赖 Google 服务、零第三方依赖，
APK 只有 **53 KB**。

> 这是 [`Android_HA_Viewer`](https://github.com/Xixixiao2007/Android_HA_Viewer) 的
> 特化分支。上一代是通用的「任意实体变化流水」，这一代只服务 F1 赛事控制。
> 两者包名不同（`com.haf1.racecontrol` vs `com.haf1.entitylist`），**可以同时装在一台手机上**。

---

## 它解决什么问题

原始的 HA App 或者一个通用的实体列表，在比赛时会变成这样：

- 一个比赛周末 **697 条消息**，其中 **54.8% 是噪音**（蓝旗、解除、删圈速通报）；
  正赛里这个比例高达 **68.5%** —— 蓝旗一项就占 42.9%
- 双黄旗一个周末 **142 条**，但它只对应 **24 个真实事件**
  （F1 的赛道系统会把一次事故扩散到几十个扇区，最极端的一次：52 条消息、20 个扇区、持续 284 秒）
- 如果你让每条双黄都报警，一个周末会被自己的手机吓 **146 次**

这个 App 把这些都处理掉了。

## 功能

### 新消息闪动

到达的新消息先闪两下再定格到等级配色。**历史回填不会闪**（否则一次回填几十条会整屏乱闪）。
同一秒内到达多条时只闪最新那条（实测峰值 7 条/秒）。

### 红旗 / 安全车 / VSC 强提醒

全屏横幅 + **循环警报音** + 震动 + 点亮屏幕。

- 走 **闹钟通道**，**突破系统静音/振动模式**（可在设置里关）
- 不同类型给不同震动节奏：红旗三长震、安全车两震、VSC 一长震、双黄三短震
- **锁屏上也能看到**（全屏横幅 + 通知栏各一条）
- 「知道了」按钮停止；不点也会在 15 秒后自动停（可配）

> 全屏横幅和通知栏两条都要：横幅负责"当场叫醒你"，但它转瞬即逝 ——
> 你要是正好没看手机，回头完全不知道刚才响过什么。通知栏那条会留着，
> 下拉就能看到是哪条旗语。

### 双黄旗：不会炸响你

双黄旗到达时先给**轻提醒**（一声短音 + 一短震），同时挂一个定时器；
**存活超过 15 秒**仍未清除才升级为全屏强提醒。

为什么要这样：实测双黄旗的存活时长是双峰的 ——

| 存活时长 | 次数 | 判读 |
| --- | --- | --- |
| 0–5 秒 | 8 | 系统抖动 |
| 6–15 秒 | 21 | **测试或瞬时** |
| 16–60 秒 | 19 | 局部事故 |
| 1–5 分钟 | 21 | 真事故 |
| > 5 分钟 | 14 | 重大事故 |

最短只有 1 秒。**3 秒的双黄不可能是真事故。** 所以「存活 ≤15 秒」是干净的判据，
而且因为闪动是即时的，不会损失任何信息。

警报的单位是「**一次事故**」而不是「一个扇区」：一次大事故会持续几分钟、
期间不断有新扇区被标双黄。事故之间用**静默间隔**划界（45 秒 —— 实测双黄消息的
间隔分布在 30 秒处有个天然断档）。

一个周末的警报次数：**146 次 → 23 次**。

> 23 次是用**真实客户端代码**在 697 条真实数据上跑出来的，不是估算：
> 3 次红旗 + 1 次 VSC + 19 次双黄事故。
> 另有一个独立写的 Python 模型在同一份数据上算出 21 次，两者相差 10% 以内。

### 顶部赛道状态条

```
┌────────────────────────────────────────┐
│ 双黄旗    扇区 12,13,14,15              │
└────────────────────────────────────────┘
```

按 **RED > 安全车 > VSC > 双黄 > 黄 > 绿** 的优先级显示当前状态，
高优先级状态生效期间锁定显示，不被随后涌入的双黄消息覆盖。

### 判罚的中文简述

仲裁消息又长又全是术语：

```
FIA STEWARDS: TURN 1 INCIDENT INVOLVING CAR 5 (BOR) NOTED -
FAILING TO FOLLOW RACE DIRECTORS INSTRUCTIONS – ESCAPE ROAD INSTRUCTIONS (14:27:29)
```

比赛时根本没空读。所以列表里每条下面补一行中文：

> **1 号弯事故（博尔托莱托(5)）：已记录 —— 未遵守赛会指令（逃生通道）**

判罚尤其讲究，谁被罚、罚多少、为什么，一眼要能看出：

> **★ 判罚：塞恩斯(55) 罚时 5 秒**
> **★ 判罚：加斯利(10) 罚时 5 秒 —— 维修区超速**
> **仲裁：塞恩斯(55) 已执行 5 秒罚时**

覆盖仲裁裁决、事故记录、超赛道限制删圈速、黑白旗、蓝旗。
**翻不出来就不显示**（宁可给原文，也不瞎猜）。规则全部是从真实数据的措辞反推的，
三位车手缩写会转成中文姓。

### 默认噪音过滤

顶部一键切换「精简 / 全部」。默认隐藏：蓝旗、解除、删圈速通报。

### 断线告警

**这条比强提醒本身还重要。** 比赛中 App 掉线时，你会以为「赛道没消息」，
实际是漏了红旗 —— 静默失败比崩溃危险。

- 顶部常驻连接状态：实时 / 重连中 / 轮询
- 掉线超过 45 秒（可配）主动提醒
- 用 `sequence` 属性检测**丢号**，跳号即在状态行标出

### 其它

- 按车号筛选（输入 `44` 只看 Hamilton 相关）
- 本地留存最近 500 条，重开不丢，离线可回看上一场
- 自由关键词排除

## 安装与配置

1. 从 [Releases](../../releases) 下载 APK，拷到手机，开启「未知来源」后安装
2. 在 HA 网页版 → **个人资料 → 安全 → 长期访问令牌 → 创建令牌**，复制那串 `eyJ...`
   （**普通权限用户即可，不需要管理员**）
3. 首次启动会自动弹出设置页，填入：
   - 服务器地址：如 `http://homeassistant.local:8123`
   - 长期访问令牌
   - 实体 ID：默认 `sensor.f1_race_control_2`
4. 点「测试连接」验证，再点「保存」

### 前置条件

需要 Home Assistant 装了 [Nicxe/f1_sensor](https://github.com/Nicxe/f1_sensor)
自定义集成，并且**开启了赛事控制的实时传感器**。本 App 读的是它提供的：

| 属性 | 用途 |
| --- | --- |
| `flag` | 旗语分类 |
| `category` | 安全车 / VSC 的唯一判据 |
| `sector` / `scope` | 状态条显示哪些扇区 |
| `car_number` | 按车筛选 |
| `event_id` | 去重 |
| `sequence` | 丢号检测 |

## 两个实现上的坑（值得单独说）

这两个都是「照抄上游文档就会写错」的取值，代码里都有对应的回归测试钉住：

**1. 安全车 / VSC 没有 `flag`。** 上游作者自己的自动化蓝图把 `VSC` `SC` 列为
`flag` 的取值，但真实数据里是：

```
flag=""   category="SafetyCar"   message="VSC DEPLOYED"
```

按 `flag` 判断会**永远不触发**。

**2. 旗语是 `BLACK AND WHITE` 一个值**，不是 `BLACK` / `WHITE` 两个。

## 开发

整套构建不需要 Gradle / Android Studio / JDK 17，一次完整构建约 10 秒。

```bash
python tools/fetch_sdk.py              # 首次：下载最小 Android 工具集（约 236 MB）
python tools/run_tests.py              # 桌面单测（134 项）
python tools/build_apk.py              # 构建 APK
python tools/run_all_tests.py          # 全套测试（单元 + mock 自测 + 端到端），共 6 项
python tools/try_feel.py               # 真机手感测试台：按键就往手机推一段剧本
```

### 发版

```bash
python tools/release.py                               # 只检查（构建 + 过两道版本号闸门）
python tools/release.py --publish --notes <说明.md>    # 检查通过后一路发到底
```

**发版前必须改 `app/AndroidManifest.xml` 的 `versionCode`（每次 +1）和
`versionName`（patch 位）。** 不改的话 `release.py` 会直接拒绝 —— 有两道闸：

1. **本地**：源码变了但 versionCode 没变
2. **远端**：该版本号已发布过，把远端资产下回来比对后发现内容不一样

> 为什么要有这个：v2.0.0 期间连着重建了 4 次、每次覆盖同一个 Release 资产，
> 结果 **4 个不同的 APK 全叫 `2.0.0`**（versionCode 都是 1）。
> 用户分不出自己装的是哪一个，先下载的人手里还是旧文件。
> 一道闸是纪律，一道是兜底。

`tools/mock_ha.py` 是个本地的假 Home Assistant（REST + WebSocket），
可以**回放 697 条真实比赛消息**，也能跑剧本：`red_flag` / `safety_car` / `vsc` /
`test_double_yellow` / `penalty` / `race_start` / `burst`。
比赛两周才有一次，用它就能随时在真机上端到端验证。

**剧本里的每条消息都是逐字取自真实数据的完整句子**，不是编的短句 ——
比如超赛道限制在真实数据里写的是
`CAR 44 (HAM) TIME 1:34.625 DELETED - TRACK LIMITS AT TURN 17 LAP 20 14:17:09`，
而不是 `TRACK LIMITS AT TURN 4`。用假短句测，测的就不是分类、过滤、翻译的真实输入。
唯一的例外是安全车那两条：那一整个周末只出了 VSC，没有真安全车。

`tools/try_feel.py` 是给真机手感用的：自动探测局域网 IP、起假 HA、把手机该填的
三项打在屏幕上，然后按数字键就往手机推一段剧本。开局停在「没比赛」状态，
不会一上来就用历史回填把屏幕刷满。

  如需公网访问，请配置 SSL 或使用 WireGuard / Tailscale 等 VPN
