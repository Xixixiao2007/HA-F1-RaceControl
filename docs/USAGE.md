# HA-F1-RaceControl —— 使用说明

**交付物**：`HA-F1-RaceControl-v2.0.5.apk`（60.7 KB，versionCode 6 / versionName 2.0.5，
minSdk 23 / targetSdk 23，Android 6.0 及以上）

桌面上显示的名字是 **F1 Race Control**。

> 与上一代 `HA Viewer`（`com.haf1.entitylist`）**包名不同**，
> 两个 App 可以同时装在一台手机上，互不覆盖。

---

## 一、装之前要有什么

### 1. Home Assistant 侧

装 [Nicxe/f1_sensor](https://github.com/Nicxe/f1_sensor) 这个自定义集成，
并且在它的设置里**开启赛事控制的实时传感器**。

装好后你会在 HA 里看到一个 `sensor.xxx_race_control` 实体
（本 App 默认填的是 `sensor.f1_race_control_2`）。

**没比赛的时候它是 `unavailable`** —— 这是正常的。它只在 F1 赛事实时数据
可用时才有值。所以别在周三测试说"没数据"。

### 2. 取一个长期访问令牌

HA 网页版 → 点左下角你的用户名 → **安全** 标签 → 拉到最下面
**长期访问令牌** → **创建令牌** → 起个名字（比如 `F1 App`）→ 复制那串 `eyJ...`。

> **普通权限用户就够，不需要管理员。** 本 App 只读，不写任何东西。

这串令牌只显示一次，先粘到别处存好。

## 二、装 App

1. 从 [Releases](../../releases) 下载 `HA-F1-RaceControl-v2.0.5.apk`
2. 拷到手机（数据线 / 网盘 / `adb install` 都行）
3. 手机上打开这个文件，系统会问「是否允许安装未知来源应用」，允许后安装

Android 6.0 上如果提示「解析包时出现问题」，多半是文件传输过程中损坏了 ——
重新拷一次，或者核对 SHA256（见 Release 说明）。

## 三、首次配置

首次启动会自动弹出设置页。

| 项 | 填什么 |
| --- | --- |
| **服务器地址** | 局域网：`http://homeassistant.local:8123`，或者 HA 的 IP，如 `http://192.168.1.40:8123` |
| **长期访问令牌** | 上面复制的那串 `eyJ...` |
| **实体 ID** | `sensor.f1_race_control_2`（或你自己那个以 `_race_control` 结尾的实体） |

点 **「测试连接」**。成功会显示：

```
已连上 HA（API running.）
实体：F1 - Officials Race control  当前值 = unavailable
```

看到 `unavailable` 是**对的**（没比赛时就是这样）。只要不是报错就说明配置正确。

然后点 **保存**。

> **公网访问**：如果 HA 暴露在公网（比如通过 DDNS 或反向代理），
> 地址可以直接填那个域名。但**明文 `http://` 会让令牌在网络上裸奔** ——
> 建议配 SSL，或者用 WireGuard / Tailscale 之类的 VPN。

## 四、界面上有什么

```
┌──────────────────────────────────────────┐
│ 双黄旗   区段 12,13,14,15          设置 │  标题栏 = 旗语（整条按级别上色）
├──────────────────────────────────────────┤
│ ⚡ 实时   128/412 条              精简    │  状态行 + 过滤开关
├──────────────────────────────────────────┤
│ ▌ 21:47:35  双黄旗                       │  左侧色条 + 类型徽标
│   DOUBLE YELLOW IN TRACK SECTOR 12       │  消息正文
│                                          │
│ ▌ 21:47:35  黄旗                         │
│   YELLOW IN TRACK SECTOR 11              │
└──────────────────────────────────────────┘
```

### 标题栏 = 旗语

标题栏整条按当前最高级别上色，左边是大号旗语，中间是区段，右边是设置键。
扫一眼就知道现在什么状况 —— 不用去列表里找。

优先级：**红旗 > 安全车 > 虚拟安全车 > 双黄旗 > 黄旗 > 绿旗**

高优先级状态生效期间会**锁定显示**，不会被随后涌入的双黄消息刷掉。
解除信号是 `TRACK CLEAR` 或 `GREEN LIGHT`。

> 这里原来显示的是传感器实体 ID（`F1 Race Control · sensor.f1_race_control_2`）——
> 那串东西只有配置的时候有用，比赛时占着最显眼的位置毫无意义。现在它只在设置页里出现。

### 状态行

`⚡ 实时` 表示 WebSocket 已连上（延迟约 50~150 毫秒）。
显示 `⏱ 轮询` 或 `⏱ 重连中` 表示实时断了，正在走 REST 兜底（延迟约 3.5 秒）。

**⚠丢号 N** 表示检测到 `sequence` 跳号 —— 说明中间漏了消息。
出现这个要留意，最好检查一下网络。

### 精简 / 全部

点右上角那个词切换。

- **精简**（默认）：隐藏蓝旗、解除、删圈速通报。
  实测这些占全部消息的 **54.8%**，正赛里占 **68.5%**
- **全部**：一条不落

## 五、提醒是怎么触发的

### 会响的

下面这几种**除了全屏横幅，还会在通知栏留一条**（锁屏上也可见）。
横幅负责当场叫醒你，通知栏那条负责事后还能查到 —— 你要是正好没看手机，
回头下拉一下就知道刚才响的是什么旗语。

| 事件 | 响应 |
| --- | --- |
| **红旗** | 全屏红 + 循环警报音 + 三长震 + 点亮屏幕 + 通知栏 |
| **安全车部署** | 全屏橙 + 循环音 + 两震 + 点亮屏幕 + 通知栏 |
| **VSC 部署** | 全屏黄 + 循环音 + 一长震 + 通知栏 |
| **双黄旗持续 >15 秒** | 全屏黄 + 音 + 三短震 + 通知栏 |
| **双黄旗刚出现** | 一声短音 + 一短震（不弹全屏） |
| **黄旗 / 黑白旗** | 一声短音 + 一短震 |
| **安全车结束 / VSC 结束** | 一声短音 + 一短震（不再吓一次） |

**超强提醒默认突破静音模式**（走闹钟通道）。现场看比赛时手机多半是静音，
不突破就可能漏掉红旗。可以在设置里关掉。

### 不会响的

- CLEAR 解除
- 蓝旗
- 圈速因超赛道限制被删
- 绿灯、格子旗（只闪动 + 配色）

> **仲裁「复核完毕，不予追究」也不会响，但它不会被隐藏。**
> 它看起来像"查完没事"，其实是一次事故的**结论** ——
> 你要能知道「刚才那个事故，赛会看过了，不罚」。所以它在列表里看得见，
> 只是不吵你。

### 关于双黄旗的特别说明

**双黄旗不会立刻弹全屏。** 它先给一次轻提醒，然后等 15 秒：

- 15 秒内收到该区段的 `CLEAR` → 判定为**系统测试**，不升级
- 15 秒后仍未清除 → 升级为全屏超强提醒

为什么这么做：实测一个比赛周末有 **142 条**双黄消息，但只对应 **24 个真实事件**。
如果把每条都当超强提醒，你一个周末会被自己的手机吓 **146 次**。

而且双黄旗的存活时长分布是双峰的，最短只有 **1 秒** ——
3 秒的双黄不可能是真事故，那就是赛道系统的测试或抖动。

因为闪动是即时的，**你不会损失任何信息**，只是不会被吵。

可以在设置里改成：

- 只闪动，不提醒
- 只轻提醒，不升级
- 轻提醒 + 仅**大面积**（同时 ≥3 个区段）才升级（最安静，**实测约 10 次/周末**）

默认这一档（轻提醒 + 持续超时升级）**实测约 23 次/周末**：
3 次红旗 + 1 次 VSC + 19 次双黄事故。这个数是用真实客户端代码在
697 条真实比赛数据上跑出来的，不是估算。

## 七、遇到问题

**「测试连接」报 401 未授权**
令牌错了、失效了，或者该用户没这个实体的读取权限。
注意 HA 对**权限不足也返回 401**（不是 403），所以别只怀疑令牌拼错。
去 HA 里重新建一个长期访问令牌。

**「404 找不到：实体 ID 可能写错了」**
实体 ID 不对。去 HA 的「开发者工具 → 状态」里搜 `race_control`，把完整 ID 抄过来。

**列表一直空着，状态行显示 `⚡ 实时`**
正常 —— 没比赛时实体是 `unavailable`，不产生任何变化。
挑一场 F1 赛事的练习赛、排位赛或正赛再看。

**状态行显示 `⏱ 重连中` 很久**
检查手机能不能访问 HA 的地址。App 会自动指数退避重连（1→2→4→…→30 秒），
重连期间自动降级为 REST 轮询，列表不会断。
如果掉线超过 45 秒，App 会主动响一声提醒你 ——
**这是故意的**，比赛中掉线最危险：你会以为赛道没消息，实际是漏了红旗。

**警报音不响**
检查手机是不是把**闹钟音量**调成 0 了（超强提醒走的是闹钟通道，不是通知通道）。
或者去设置里关掉「突破静音模式」。

**超强提醒没有弹出全屏**
Android 6.0 上如果开启了「悬浮窗」类的系统限制，或者有省电优化策略，
后台弹窗可能被拦。把本 App 加入电池优化白名单。

**中文显示成方块**
Android 6.0 自带中文字体，正常不会。如果刷了精简 ROM 缺字体，只能换 ROM。

## 八、怎么在不比赛的时候测试

比赛两周才有一次。想在平时验证 App 行为，用仓库自带的 mock 服务器：

```bash
# 真机联调：必须监听 0.0.0.0，手机才连得上。token 自己定
python tools/mock_ha.py --host 0.0.0.0 --port 8123 --token my-token

# 或者直接演剧本（每步 2 秒，循环）
python tools/mock_ha.py --scenario red_flag --loop
```

它会起一个假的 HA（REST + WebSocket，和真 HA 同协议同端口），
可以回放**真实的 697 条比赛消息**，也能跑剧本：
`race_start` / `red_flag` / `safety_car` / `vsc` / `test_double_yellow` / `burst`。

把手机上的服务器地址改成这台电脑的 IP（比如 `http://192.168.1.6:8123`），
令牌填 `--token` 指定的值，就能在真机上把闪动、分级、超强提醒、确认、重连全测一遍。

常用参数：

| 参数 | 用途 |
| --- | --- |
| `--speed 400` | 400 倍速压缩回放整个比赛周末（真实跨度 51 小时，约 8 分钟播完） |
| `--speed 0` | 全速灌 697 条，压测突发 |
| `--start-offset 30` | 先空转 30 秒再开始回放，用来验证"没比赛时列表空着"的显示 |
| `--loop` | 播完从头再来 |

运行中还能不重启切剧本：

```bash
curl -X POST "http://127.0.0.1:8123/_mock/scenario?name=red_flag"
```

开发侧跑全套测试：

```bash
python tools/run_all_tests.py
```

它会依次跑①单元测试 ②mock 服务器自测 ③端到端（真实客户端代码连假 HA，
含真实数据回放和三个剧本）④发布工具对象重建自测，最后给一张汇总表。

## 十、隐私

- 本应用**不收集任何数据**，没有分析、没有崩溃上报、没有第三方 SDK
- 所有通信只发生在你的手机与你的 Home Assistant 之间
- 令牌保存在手机本地的 `SharedPreferences` 里
- 权限只有两个：`INTERNET`（连 HA）和 `VIBRATE`（震动）
